# みんなの雑学クイズ

Cloudflare Pagesで公開する静的フロントエンドと、Google Apps Script（GAS）、Googleスプレッドシートを組み合わせた4択クイズゲームです。

カテゴリー・難易度・問題数を選んで回答すると結果が表示され、プレイヤー名と100点満点のスコアをスプレッドシートへ保存できます。ランキングに加え、端末内に苦手問題と成長記録も保存します。

> このアプリは学習用・作品展示用です。正解情報はブラウザへ送られるため、不正を完全には防げません。正式な試験や成績評価には使用できません。

## ファイル構成

```text
quiz-game/
├── index.html
├── style.css
├── app.js
├── README.md
└── gas/
    ├── Code.gs
    ├── MusicQuestions.gs
    └── QuestionBank.gs
```

## 主な機能

- GASから有効な問題を取得
- カテゴリー・難易度・5問／10問／20問を選択
- 取得した問題をシャッフルして出題
- 4択回答、正誤表示、解説表示
- 問題数にかかわらず100点満点で採点
- 間違えた問題だけに再挑戦できる復習モード
- 連続正解コンボと成績に応じた称号
- 挑戦回数・最高得点・通算正答率・苦手カテゴリーを端末に保存
- プレイヤー名と結果をスプレッドシートへ保存
- スコア・正解数・登録日時を使った上位10件ランキング
- スマートフォン対応
- 通信中・通信失敗時のメッセージ表示
- 同一プレイ結果の二重登録防止
- 6桁メールOTPを使った段階式アカウント作成
- メールアドレスとパスワードによるログイン・セッション維持
- 本人だけが編集できるプロフィールとプロフィールアイコン
- 基本情報技術者試験A分野に沿ったオリジナル練習問題

ログイン機能の初期設定は [AUTH_SETUP.md](./AUTH_SETUP.md) を参照してください。

## 1. Googleスプレッドシートを作成する

1. Googleドライブを開きます。
2. 「新規」→「Googleスプレッドシート」を選びます。
3. ファイル名を「みんなの雑学クイズ」などに変更します。
4. この時点ではシート名や列を手作業で設定する必要はありません。

## 2. Apps Scriptを開く

1. 作成したスプレッドシートを開きます。
2. メニューの「拡張機能」→「Apps Script」を選びます。
3. Apps Scriptエディタが別タブで開きます。
4. プロジェクト名を「みんなの雑学クイズAPI」などに変更します。

## 3. Code.gsを設定する

1. Apps Scriptエディタに最初からあるコードを削除します。
2. `gas/Code.gs` の内容をコピーして、GASの `Code.gs` に貼り付けます。
3. GASで新しいスクリプトファイル `QuestionBank.gs` を作り、`gas/QuestionBank.gs` の内容を貼り付けます。
4. 同様に `MusicQuestions.gs` を作り、`gas/MusicQuestions.gs` の内容を貼り付けます。
5. 保存ボタンを押します。

この手順のようにスプレッドシートからApps Scriptを開いた場合は、スプレッドシートに紐づいたスクリプトになります。そのため、通常は次の設定を空のまま使用できます。

```javascript
const SPREADSHEET_ID = '';
```

スプレッドシートとは別にApps Scriptプロジェクトを作成した場合は、スプレッドシートURLの `/d/` と `/edit` の間にあるIDを設定してください。

```javascript
const SPREADSHEET_ID = 'ここにスプレッドシートID';
```

## 4. スプレッドシートを初期設定する

1. Apps Script上部の関数選択欄で `setupSpreadsheet` を選びます。
2. 「実行」を押します。
3. 初回のみ、Googleアカウントの認証画面が表示されます。
4. 使用するGoogleアカウントを選び、内容を確認して許可します。
5. スプレッドシートに `questions` と `scores` の2シートが作成されたことを確認します。
6. `questions` シートにはサンプル問題が240問追加されます。

### questionsシート

```text
id | question | choice1 | choice2 | choice3 | choice4 | correct | explanation | enabled | category | difficulty
```

- `correct` は正解の選択肢番号（1〜4）です。
- `enabled` が `TRUE` の問題だけが出題されます。
- `category` は `一般常識`、`科学`、`歴史`、`地理`、`食べ物`、`スポーツ`、`音楽` のいずれかです。
- `difficulty` は `かんたん`、`ふつう`、`むずかしい` のいずれかです。
- 空欄がある問題や、正解番号が1〜4以外の問題は除外されます。

古い9列構成のシートは、最初の問題取得時に新しい2列と不足するサンプル問題が自動追加されます。全240問で、「基本情報技術者」カテゴリーに50問、その他のカテゴリーに27〜28問があります。問題は試験問題の転載ではなく、A分野を学ぶためのオリジナル練習問題です。

### scoresシート

```text
timestamp | playerName | score | correctCount | totalQuestions
```

スコア登録時に自動で行が追加されます。

## 5. GASをWebアプリとしてデプロイする

1. Apps Script右上の「デプロイ」→「新しいデプロイ」を選びます。
2. 「種類の選択」から「ウェブアプリ」を選びます。
3. 説明に「初回デプロイ」などを入力します。
4. 「次のユーザーとして実行」は自分（デベロッパー）を選びます。
5. 「アクセスできるユーザー」は「全員」を選びます。
6. 「デプロイ」を押します。
7. 必要な場合は、もう一度アクセス権を許可します。
8. 表示されたWebアプリURLをコピーします。

URLは次のような形式です。

```text
https://script.google.com/macros/s/デプロイID/exec
```

## 6. フロントエンドへGASのURLを設定する

`app.js` の先頭付近にある定数を、コピーしたWebアプリURLへ変更します。

```javascript
const GAS_WEB_APP_URL = "ここにGASのWebアプリURLを入力";
```

このリポジトリでは既定のWebアプリURLが入力されています。別のGASプロジェクトへデプロイした場合だけ差し替えてください。

フロントエンドはGET通信だけを使います。リポジトリの規約に合わせて `mode` パラメータを送り、互換性のため同じ値を `action` にも設定します。GAS側はどちらでも処理できます。

```text
?mode=getQuestions&action=getQuestions
?mode=saveScore&action=saveScore
?mode=getRanking&action=getRanking
```

ブラウザからGASへの通常の `fetch` がCORSで拒否された場合は、自動的にJSONP通信へ切り替わります。

## 7. ローカルで確認する

HTMLファイルを直接開くより、簡単なローカルサーバーを使う方法がおすすめです。

Pythonがインストールされている場合は、`quiz-game` フォルダで次を実行します。

```powershell
python -m http.server 8000
```

ブラウザで次を開きます。

```text
http://localhost:8000
```

確認後はターミナルで `Ctrl + C` を押して終了します。

## 8. Cloudflare Pagesへ公開する（GitHub経由）

1. GitHubにリポジトリを作成します。
2. `quiz-game` のファイルをリポジトリへpushします。
3. Cloudflare Dashboardへログインします。
4. 「Workers & Pages」→「Create」→「Pages」→「Connect to Git」を選びます。
5. 対象のGitHubリポジトリを選びます。
6. フレームワークは「None」を選びます。
7. ビルドコマンドは空欄にします。
8. 出力ディレクトリは、リポジトリ直下にファイルがある場合は `/`、この構成のままなら `quiz-game` を指定します。
9. 「Save and Deploy」を押します。
10. 発行された `pages.dev` のURLで動作確認します。

GitHubへ変更をpushすると、Cloudflare Pagesが自動で再公開します。

## 9. Cloudflare Pagesへ公開する（直接アップロード）

1. Cloudflare Dashboardの「Workers & Pages」を開きます。
2. 「Create」→「Pages」→「Upload assets」を選びます。
3. プロジェクト名を入力します。
4. `quiz-game` フォルダ内の次のファイルをアップロードします。

```text
index.html
style.css
app.js
```

5. 「Deploy site」を押します。
6. 発行されたURLで動作確認します。

`README.md` と `gas/Code.gs` は説明・バックエンド用ファイルなので、静的サイトの表示には必須ではありません。

## 10. GASコードを変更したとき

GASの `/exec` URLは、コードを保存しただけでは新しい内容に切り替わらない場合があります。

1. 「デプロイ」→「デプロイを管理」を開きます。
2. 使用中のWebアプリの編集ボタンを押します。
3. バージョンで「新バージョン」を選びます。
4. 説明を入力します。
5. 「デプロイ」を押します。
6. 同じWebアプリURLで新しい動作を確認します。

## APIの動作確認

WebアプリURLの末尾にパラメータを付けてブラウザで開きます。

```text
?mode=getQuestions
?mode=getRanking
```

成功時は次の形式で表示されます。

```json
{
  "success": true,
  "data": {}
}
```

## よくあるエラーと対処法

### 「app.jsにGASのWebアプリURLを設定してください」と表示される

`app.js` の `GAS_WEB_APP_URL` が正しい `/exec` URLになっているか確認します。

### Googleのログイン画面が表示される

Webアプリの「アクセスできるユーザー」が「全員」になっていない可能性があります。デプロイ設定を確認してください。

### GASを修正したのに画面へ反映されない

「デプロイを管理」から新しいバージョンとして再デプロイしてください。ブラウザ側は `Ctrl + F5` で再読み込みします。

### 「questionsシートがありません」と表示される

Apps Scriptで `setupSpreadsheet` を手動実行してください。シート名を手作業で変更していないかも確認します。

### 「出題できる有効な問題がありません」と表示される

`questions` シートで、問題文・4つの選択肢・正解番号・解説が入力されているか、`enabled` が `TRUE` になっているか確認します。

### 初回認証が終わっていない

Apps Scriptエディタで `setupSpreadsheet` を実行し、表示された認証画面でアクセスを許可してください。

### 通信に失敗する、またはタイムアウトする

- インターネット接続を確認します。
- GASのWebアプリURLが正しいか確認します。
- Webアプリが「全員」に公開されているか確認します。
- しばらく待ってから再度実行します。
- ブラウザの開発者ツールにエラーが出ていないか確認します。

### スプレッドシートへのアクセス権がない

Webアプリの実行ユーザーをデベロッパーに設定します。`SPREADSHEET_ID` を指定した場合は、そのIDが正しいか確認します。

### スコアが二重に登録される

フロントエンドでは登録後にボタンを無効化しています。ページを複数タブで開いた場合などは完全には防げないため、作品展示時は同じ端末で連打しないようにしてください。

## セキュリティ上の注意

- 本名・メールアドレス・住所などは入力しないでください。
- プレイヤー名はニックネームを使用してください。
- GAS側でも名前・スコア・正解数・問題数を検証しています。
- `=`, `+`, `-`, `@` から始まる名前は、スプレッドシート上で数式にならないよう無害化します。
- パスワードや秘密情報はフロントエンドやURLに含めないでください。
- 正解情報はフロントエンドへ送られるため、正式な試験には向きません。
